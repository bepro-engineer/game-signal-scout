# 設計（DESIGN）

> **取得元はすべて同列の交換可能な入力で、どれもなくてまったく困らない（外しても残りの取得元だけで動く）。特定の取得元を中心に置かない・目立たせない・個別に名前を挙げて取り上げない**（オーナーの厳命。[CLAUDE.md](../CLAUDE.md)）。

## 1. 目的と提供価値

読者は、仕事で自由な時間が限られた人です。週末・連休に、自分に合い満足できる PC・家庭用のゲームを選びたい。そのため Game Signal Scout は、世界のプレイヤーの声から、ストアの紹介や人気の順位では見えない変化を見つけて示します（Issue #2）。

- 評価が動いた作品と、その理由（アップデートの影響・不具合・不満・価格・論争）
- 話題が言語圏を越えて広がった作品、話題が再燃した作品
- これから発売の作品と、その前の話題

根拠のない推薦・満足度・クリアまでの時間・向き不向きは作りません。人数は取得元ごとに数え、取得元をまたいで足しません。

## 2. ドメインのモデル

| 概念 | 表 | 説明 |
|---|---|---|
| 作品 | `game_profile` | Steam の app ID が鍵。題名（日本語のストアの表示・各言語の題名 `names`）・画像・ゲーム内容（日・英）・ジャンル・遊び方・機種・日本語・発売日・発売前か。ゲームでないソフト（ユーティリティなど）は作品にしない |
| 発言 | `player_post` | 取得元・ID・時刻・投稿者（取得元の中の参照。名前や ID は hash にして持つ）・言語・作品（app ID と同定の方法 `matched_by`: `source`／`steam_link`／`title`）・本文・印（宣伝など）。レビューは肯定／否定と遊んだ時間も持つ |
| 観測 | `obs_post`・`obs_work_lang_day`・`obs_day_state` | 取得元 × 日（日本時間 3:00 区切り）× 作品 × 言語の独立した投稿者の数と、その日がそろったか |
| 規模・これから | `game_activity`・`game_upcoming` | Steam の最も遊ばれているゲームの順位・人気の近日発売の順位（補助。満足度の根拠にしない） |
| 今日の兆し | `job_artifact` | 日ごとの LLM の発見（入力の鍵・生成の版・合否） |
| 公開の文書 | `public_document`・`public_build` | 画面が読む文書。検査に通ったときだけ置き換える |
| 動作の報告（補助） | `player_report`・`shift_event` | ProtonDB（Linux・Steam Deck の動作）。取得元の 1 つで、全体の主役にはしない |

## 3. 処理の流れ（日次 `daily-run`）

1. **collect**: 記述のある取得元を読む（前回の成功から `min_interval_hours` の間は読まない。1 つの失敗で他を止めない）。
2. **normalize**: 記述の `normalizer` で共通の表へ。作品の同定は `services/identify.py`。
3. **observe**: 直近 28 日の観測の集計を作り直す（削除・取り直しへの追従）。
4. **analyze**: 動作の報告の変化（ProtonDB。補助）。
5. **insight**: 無効（`config/daily.toml` の `[insight] enabled = false`。オーナーの判断）。
6. **digest**: 今日の兆し。作品ごとに、観測の集計に入れているすべての取得元の声（`voice_sources = "all"`）を共有の LLM で読み、話題を見つけ、検査（数・引用・言語・見出しの長さ・言い過ぎ）に通ったものだけ。
7. **publish**: 文書を作って検査し、`public_document` を置き換える。

声の取得元は、どれも同じ形の常駐の収集器（取得元ごとの `collect-<取得元>`。Anime と同じ）で、記述の `poll_seconds` ごとに読みます。日次の段は、それを全取得元に同じに正規化・集計します。

## 4. 取得元ごとの約束

取得元の一覧・条件・判定（ready／needs_key／needs_decision／rejected）と、外すための手順は [config/source_candidates.toml](../config/source_candidates.toml) が正本です。共通の約束は次のとおりです。

- ログイン・年齢確認・Cloudflare の遮断・robots.txt の禁止は回避しません。Crawl-delay を守ります（ニコニコ大百科・はてな 5 秒）。
- 投稿者の名前・ID は持ちません（取得元ごとの hash）。
- 削除への追従: 取得元が消えた項目を返すもの（全件の配布物など）は消し、消えた事実は `source_gone` に残します。Steam のレビューは版（更新時刻）が変われば置き換えます。
- 保留: Steam の掲示板・ワークショップ・告知へのコメント（Steam の利用規約 4.C。オーナーの指示）。

## 5. 公開の基準

- 画面に出す日は、Game が観測を始めた日から（`[publish] start_day`）。それより前の日は「普段」を測るためだけに使う。
- 日がそろわない（取得元の一部がそろっていない）日は、そのことを画面に示す（Anime と同じ `obs_status`）。
- 今日の兆しは、検査に通った文だけ。通らなければ事実だけの要約（集計の数）を出す。
- 公開の文書は、公開してよい項目の検査（`content.audit_public`）に通ったときだけ置き換える。
