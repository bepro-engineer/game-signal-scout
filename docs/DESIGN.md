# 設計（DESIGN）

> **取得元はすべて同列の交換可能な入力で、どれもなくてまったく困らない（外しても残りの取得元だけで動く）。特定の取得元を中心に置かない・目立たせない・個別に名前を挙げて取り上げない**（オーナーの厳命。[CLAUDE.md](../CLAUDE.md)）。

## 1. 目的と提供価値

読者は、仕事で自由な時間が限られた人です。週末・連休に、自分に合い満足できる PC・家庭用のゲームを選びたい。そのため Game Signal Scout は、世界のプレイヤーの声から、ストアの紹介や人気の順位では見えない変化を見つけて示します（Issue #2）。

- 評価が動いた作品と、その理由（アップデートの影響・不具合・不満・価格・論争）
- 話題が言語圏を越えて広がった作品、話題が再燃した作品
- これから発売の作品と、その前の話題

根拠のない推薦・満足度・クリアまでの時間・向き不向きは作りません。人数は取得元ごとに数え、取得元をまたいで足しません。

## 2. ドメインのモデル

| 概念 | 表 | 説明 |
|---|---|---|
| 作品 | `game_profile` | ストアの作品番号（app ID）が鍵（**1 つのストアの番号が作品の鍵になっている。取得元に依らない鍵に直すのは残り**: #3 の最終監査・ARCHITECTURE §7）。題名（日本語のストアの表示・各言語の題名 `names`）・画像・ゲーム内容（日・英）・ジャンル・遊び方・機種・日本語・発売日・発売前か。ゲームでないソフト（ユーティリティなど）は作品にしない |
| 発言 | `player_post` | 取得元・ID・時刻・投稿者（取得元の中の参照。名前や ID は hash にして持つ）・言語・作品（app ID と同定の方法 `matched_by`: `source`／`steam_link`／`title`）・本文・印（宣伝など）。レビューは肯定／否定と遊んだ時間も持つ |
| 観測 | `obs_post`・`obs_work_lang_day`・`obs_day_state` | 取得元 × 日（日本時間 3:00 区切り）× 作品 × 言語の独立した投稿者の数と、その日がそろったか |
| 作品の属性 | `game_attribute` | 日本語の UI・字幕・音声、開発元・販売元、開発元の国・地域。作品・項目・取得元・値・取得の時刻（出典つき）。属性がなければ画面は「未確認」。推定しない |
| 作品の価格 | `game_attribute`（項目 `price`） | 日本向けの販売価格（#2 2026-11-10）: 区別（有料・無料・発売前・未確認）、国、通貨、通常価格・現在価格・割引率（割引中だけ）、確かめた時刻、ストアの作品のページ。毎日確かめ、`config/daily.toml [prices] stale_days` 日を超えた値は画面に出さない（未確認）。0 円・架空の価格・税込の断定・履歴・換算はしない。日英で国・通貨・数値は同じ |
| 作品のユーザー評価 | `game_attribute`（項目 `rating`） | ストアが示すユーザーレビューの集計（#2 2026-11-10）: 全期間（ストアの既定の表示と同じ集計）と日本語のレビューだけの集計。件数・好評の割合・評価の段階と名前（日英）。最近 30 日の集計は問い合わせ先にないので持たない。換算・推定はせず、このサイトの観測人数・読み取りと混ぜない。`config/daily.toml [ratings] stale_days` 日を超えた値は出さない |
| 規模・これから | `game_activity`・`game_upcoming` | ストアの最も遊ばれているゲームの順位・人気の近日発売の順位（補助。満足度の根拠にしない） |
| プレイヤーの発見 | `game_insight` | 作品ごとの AI の読み取り。発言から取り出した具体的な体験（何をした → 何が起きた → 面白い／不満。醍醐味の種類・遊び方・注意・1 回に遊ぶ時間〔2026-11-11 から〕）と、同じ体験をまとめたものの人数・前の週との比較、同じ論点で賛否が分かれた体験の組（`divided`。2026-11-11）。数・向き・同じ人はこちらで確かめて数える |
| 遊びたい体験の入口・賛否 | `public_document` の `pages`（`intents`・`divided`） | `services/intents` が読み取りの体験だけで選ぶ（ジャンル・ストアの分類では選ばない）。根拠のない入口は 0 件のまま |
| 今日の兆し | `job_artifact` | 日ごとの LLM の発見（入力の鍵・生成の版・合否） |
| 公開の文書 | `public_document`・`public_build` | 画面が読む文書。検査に通ったときだけ置き換える |
| 動作の報告（補助） | `player_report`・`shift_event` | 動作の報告を持つ取得元の報告（Linux・携帯機での動作）。取得元の 1 つで、画面の文書には使わない（その報告を中心にした古い公開の文書は 2026-11-11 に廃止） |

## 3. 処理の流れ（日次 `daily-run`）

1. **collect**: 記述のある取得元を読む（前回の成功から `min_interval_hours` の間は読まない。1 つの失敗で他を止めない）。
2. **normalize**: 記述の `normalizer` で共通の表へ。作品の同定は `services/identify.py`。
3. **observe**: 直近 28 日の観測の集計を作り直す（削除・取り直しへの追従）。
4. **analyze**: 動作の報告の変化（補助。画面の文書には使わない。#1 の検証の記録）。
5. **insight**: プレイヤーの発見（`services/insight`。#2）。直近 7 日と前の 7 日の発言を投稿者ごとに 1 件、AI が具体的な体験を取り出し（読んだ結果は残し、次の回は新しい発言だけ）、同じ体験をまとめる。人数・内訳・比較はこちらで数え、`min_people`（2）人以上の体験を発見にする（1 人の体験は「ひとりの体験」と明記）。続けて、同じ論点で賛否が分かれた体験の組を作り（`divide_missing`。読み取りの材料か作り方の版が変わった作品だけ）、画面の文を英訳する。1 回に `max_per_run` 作品まで。
6. **digest**: 今日の兆し。作品ごとに、観測の集計に入れているすべての取得元の声（`voice_sources = "all"`）を共有の LLM で読み、話題を見つけ、検査（数・引用・言語・見出しの長さ・言い過ぎ）に通ったものだけ。
7. **publish**: 画面が読む文書（day/・pages・search・soon・work/・days）だけを作って検査し、`public_document` を置き換える。最新の日は作った画面の日の一覧の最後（特定の取得元の日付に依らない）。

声の取得元は、どれも同じ形の常駐の収集器（取得元ごとの `collect-<取得元>`。Anime と同じ）で、記述の `poll_seconds` ごとに読みます。日次の段は、それを全取得元に同じに正規化・集計します。

## 4. 取得元ごとの約束

取得元の一覧・条件・判定（ready／needs_key／needs_decision／rejected）と、外すための手順は [config/source_candidates.toml](../config/source_candidates.toml) が正本です。共通の約束は次のとおりです。

- ログイン・年齢確認・Cloudflare の遮断・robots.txt の禁止は回避しません。ホストが宣言する Crawl-delay を守ります。
- 投稿者の名前・ID は持ちません（取得元ごとの hash）。
- 削除への追従: 取得元が消えた項目を返すもの（全件の配布物など）は消し、消えた事実は `source_gone` に残します。版（更新時刻）を持つ項目は、版が変われば置き換えます。
- 保留: ストアの掲示板・ワークショップ・告知へのコメント（ストアの利用規約 4.C。オーナーの指示）。
- 利用条件の記録: [config/source_terms.toml](../config/source_terms.toml)（取得元ごとに一次資料の URL・条項の要旨・確認日、分類 explicitly_prohibited／conditional／explicitly_allowed／unconfirmed）。判定は `source_terms.py` の 1 か所。
  - 禁止が明記された取得元は、取得・集計・公開に入れない。複数のサイトを読む取得元は、禁止のサイトだけを `excluded_hosts` に書き、記述から外し、保存済みの発言に印 `terms_excluded` を付けて集計・公開から外す（消さない）。未確認を禁止として扱わない。
  - 公開の画面に原文を引用するのは、`public_quote` が allowed と記録された取得元だけ（2026-11-08 現在 0）。AI が読む声は分析として使う。
  - 取得の共通の部品（`sources/http.Fetcher`）は、ホストの robots.txt の Crawl-delay を守る。

## 5. 公開の基準

- 画面に出す日は、Game が観測を始めた日から（`[publish] start_day`）。それより前の日は「普段」を測るためだけに使う。
- 日がそろわない（取得元の一部がそろっていない）日は、そのことを画面に示す（Anime と同じ `obs_status`）。
- 今日の兆しは、検査に通った文だけ。通らなければ事実だけの要約（集計の数）を出す。
- 画面の構成（#2）: 日本人が作品を選ぶ順に、日本語で遊べるか（UI・字幕・音声）→ 開発元と国・地域 → どんな体験か（プレイヤーの発見）→ 根拠。言語圏の広がり・人数は補助。
  「世界で広がる作品」のページは「プレイヤーの発見」（`finds.html`）に置き換えた（古い URL は転送）。
- 公開の文書は、公開してよい項目の検査（`content.audit_public`）に通ったときだけ置き換える。
- 左のメニュー（#2 2026-11-11）: ダッシュボード・注目の作品（プレイヤーが書いた細かな面白さで探す）→ 遊ぶ目的の 4 つの入口（じっくり没頭・短時間・新しい体験・友達と。`deep`・`short`・`novel`・`friends.html`）→ 賛否が分かれる作品（`split.html`。同じ論点で賛否が分かれた作品だけ）・言語圏の広がり → 作品を探す・このサイトについて。遊び方のページ（ソロ・協力・対戦・コントローラ）・まもなく発売は、作品を探す・サイドバーから。
